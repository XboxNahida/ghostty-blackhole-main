# v1.2.4 兼容性修复设计

## 目标

发布 `v1.2.4`，集中修复社区已经提供充分日志或能够从代码确认根因的兼容性问题：混合 DPI 多屏缩放、Bloom 画面放大、AMD Shader 编译失败、黑洞无法完全静止、重复 Renderer 叠加，以及 WGC 捕获帧过早释放导致的并发竞争。

本版不重新设计黑洞 Shader，不调整吸积盘光影的泛白和对比度，也不在缺少复现证据时重写多屏捕获管线。

## 修复范围

### 1. AMD Shader 兼容

桌面片元 Shader 使用 GLSL 330，却将 `fragColor` 映射到旧式 `gl_FragColor`。严格的 AMD 驱动会拒绝该保留标识符。

桌面 Shader 改为显式输出：

```glsl
out vec4 fragColor;
```

同步修改源码 Shader 和发布 Shader。预览 Shader 已使用显式输出，不改变其现有行为。测试必须确认桌面 Shader 不再包含 `gl_FragColor`，且生成的主函数仍写入全局 `fragColor`。

### 2. Bloom 全屏 UV

Bloom 使用全屏大三角形。顶点 Shader 中的 `p` 在实际可见区域已经插值为 `0~1`，现有 `uv = p * 0.5` 只采样桌面纹理左下四分之一并拉伸。

将其改为 `uv = p`。本版不修改 Bloom 提亮、色调映射或合成参数。

高级设置中“吸积盘光影效果”右侧常驻显示：

> 实验性功能，尚未完成；启用后可能出现泛白、对比度变化或画面异常

该说明不随勾选状态隐藏，避免用户启用前看不到风险。

### 3. 混合 DPI 多屏

Renderer 当前调用 `SetProcessDPIAware()`，仅达到系统 DPI 感知。在主屏 150%、副屏 100% 时，副屏窗口会按 `100/150` 缩成约三分之二。

Renderer 必须在创建任何窗口、读取显示器坐标和初始化 WGC 之前设置 DPI：

1. 优先使用 `SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)`。
2. 不支持时回退到 Per-Monitor aware。
3. 最后才回退到旧式 `SetProcessDPIAware()`。

初始化只执行一次，删除捕获模块和窗口模块中的重复旧式调用。所有 `MONITORINFO`、虚拟桌面坐标、窗口尺寸和捕获区域使用同一物理像素坐标体系。

跨屏副屏灰色与混合 DPI 高度相关，但现有证据不足以确认唯一根因。本版先修复 DPI 坐标体系并增加必要日志；若相同设备复测仍灰屏，再依据窗口矩形、捕获尺寸和上传区域日志继续定位。

### 4. 黑洞移动速度为零

移动速度范围由 `0.1~3.0` 改为 `0~3.0`，Qt 滑块、共享规范化函数、配置加载和测试保持一致。

`movementSpeed=0` 时，`uMovementTime` 保持为零，只冻结黑洞自由移动轨迹。`iTime` 仍使用真实时间，因此吸积盘动画、出生/消失动画和预设变化不被冻结。旧配置继续正常读取。

### 5. Renderer 单实例

现有控制进程 Mutex 不覆盖 `--render`。新增 Renderer 目标键：

- 主 Renderer：固定键。
- “一屏一黑洞”副屏 Renderer：按 `screenIdx` 生成独立键。

相同目标已有 Renderer 时，新进程在创建窗口和捕获会话前退出；不同屏幕的 Renderer 可以同时运行。目标键生成逻辑应抽成可测试的无副作用函数，避免字符串拼接散落在 `main.cpp`。

### 6. WGC 捕获帧生命周期

#### 已确认根因

现有 `WGC_GetFrame()` 在 `get_Surface()` 后立即释放 `IDirect3D11CaptureFrame`，随后才取得底层 `ID3D11Texture2D` 并交给主循环。释放 capture frame 后，WGC 帧池可以复用对应缓冲区并写入下一帧，而主循环尚未提交或完成 `CopyResource`，形成并发读写竞争。

现有 event query 位于 `CopyResource` 之后，只能等待已经提交的复制，无法消除 capture frame 提前释放到复制提交之间的窗口。

#### 采用方案

WGC 捕获模块内部完成一个不可拆分的稳定读取流程：

1. `TryGetNextFrame` 获取 capture frame。
2. 保持 capture frame 引用存活。
3. 获取 surface 和底层 D3D11 纹理。
4. 将纹理复制到该捕获器独立的 staging texture。
5. 使用阻塞式 `Map(D3D11_MAP_READ)` 作为复制完成边界。
6. Map 成功后释放底层纹理、surface 和 capture frame。
7. 将 mapped staging 数据返回给调用方上传到 OpenGL，上传后由调用方 Unmap。

主循环不再获得或释放 WGC 帧池纹理裸指针。主屏和副屏分别使用各自的 `WGCCapture` 与 staging texture，不共享当前帧状态。

任何获取 surface、查询接口、复制或 Map 的失败路径都必须释放本次持有的 COM 对象并返回失败；不能把 capture frame 留到下一轮隐式覆盖。设备失效保持现有诊断边界，不静默切换捕获器。

DXGI Desktop Duplication 的 Acquire/ReleaseFrame 生命周期保持原样，不与 WGC 新接口混用。

## 测试策略

修改生产代码前先建立能够在当前版本失败的回归测试或契约：

1. Shader 契约：桌面 Shader 使用显式输出且无 `gl_FragColor`。
2. Bloom 契约：全屏大三角形使用 `uv = p`。
3. 移动设置单元测试：0、范围内值和上下界钳制。
4. Renderer 目标键单元测试：主目标稳定、同屏相同、不同副屏不同。
5. DPI 契约：初始化发生在显示器枚举和窗口创建之前，模块内部不再重复降级 DPI 感知。
6. WGC 生命周期契约：WGC 不再向主循环返回帧池纹理，capture frame 的释放发生在同步 staging Map 之后；失败路径由代码审查和构建覆盖。
7. QML 契约：风险说明常驻显示，移动速度下限为 0。

阶段验证：

- 阶段一：Shader、Bloom、移动速度和 UI 契约。
- 阶段二：Renderer Mutex、DPI 和 WGC 生命周期。
- 阶段三：Renderer 与 Qt clean build、完整 CTest、Shader 运行加载、重复启动、空闲模式和多屏冒烟。
- 阶段四：同步 `1.2.4` 身份、README、发布指南与打包脚本，生成 ZIP、SHA-256 sidecar 和中文更新说明。

## 发布与兼容边界

- 保留 WGC/DXGI 自动选择和手动选择逻辑。
- 不改变用户名单、预设和高级设置文件的位置。
- 不提交收款码，但正式 ZIP 继续包含本地收款码资源。
- 不承诺解决尚无完整日志的所有灰屏、HDR 或旧显卡问题。
- 正式包必须使用 clean build，并通过现有发布身份、安全与 checksum 检查。

## 成功标准

- AMD 严格 GLSL 驱动不再因 `gl_FragColor` 拒绝桌面 Shader。
- 开启 Bloom 后桌面不再只显示放大的局部区域。
- 100% 副屏不再在 150% 主屏环境中缩成三分之二。
- 移动速度 0 可保存、加载并让自由轨迹静止。
- 同一显示目标无法同时存在多个 Renderer，不影响一屏一黑洞。
- WGC capture frame 在 staging 复制同步完成前不会释放。
- 无新增编译错误；新增警告必须说明，现有测试全部通过。
